# プロジェクト初期構想：Console Psycometrist

**日付**: 2026-02-13  
**カテゴリ**: 要件定義・設計  
**影響範囲**: プロジェクト全体

## 変更の背景

システムエンジニアにとって最も身近な「ターミナル（コンソール）」を物語の舞台として再定義し、
テキストベースのインタラクティブな体験を提供するゲームを開発することを決定しました。

グラフィックを極限まで削ぎ落とし、等幅フォントとカーソルの点滅だけでプレイヤーの没入感をコントロールする、
ミニマリスティックなアプローチを採用します。

## プロジェクトコンセプト

**プロジェクト・コードネーム**: `Console Psycometrist`  
**コンセプト**: 「コンソールを通して人の思いを読み取る」

### 美学的目標

1. **情報の等価性**: システムメッセージもキャラクターの独白も同じフォントで表示することで「現実とデータの境界」を曖昧にする
2. **タイポグラフィの美**: カーニング、行間、文字の出現速度にこだわり、テキストそのものを「演出」に昇華させる
3. **ミニマリズム**: 色数を制限し（Amber, Green, White）、80年代コンピュータのような「レトロ・フューチャー」を再現する

## 基本設計

### UIレイアウト構成

画面を3つの主要エリアに分割:

| エリア名                  | 役割                                     | 視覚的特徴                                   |
| ------------------------- | ---------------------------------------- | -------------------------------------------- |
| **Header (Status Bar)**   | 現在のディレクトリ、時刻、接続状態の表示 | 反転文字（背景色あり）で情報を固定表示       |
| **Main (Log View)**       | 物語（ログ）が流れるメインエリア         | 上から下へテキストが流れ、溢れるとスクロール |
| **Footer (Command Line)** | ユーザーの入力・選択待機場所             | `> `（プロンプト）と点滅カーソルを表示       |

### 主要システム・コンポーネント

1. **Terminal Container**: 全てのUIパーツを内包し、スキャンラインやノイズなどのポストエフェクトを一括適用
2. **Scroll Manager**: テキスト行が増えた際、古い行をスムーズに上部へ移動させる制御ロジック
3. **Command Dispatcher**: ユーザーの入力（キーボード/クリック）を解析し、適切な物語のフラグへ橋渡し

## 技術スタック

- **フレームワーク**: Phaser 3
- **言語**: TypeScript
- **フォント**: MS Gothic（等幅フォント）
- **ビルドツール**: Vite

## 実装方針

### フォントとカメラの設定

- 等幅フォント（MS Gothic）の導入
- 解像度固定でピクセルパーフェクトな質感を実現（`Phaser.Scale.FIT`、`pixelArt: true`）

### Typewriter Component

文字送り効果を実現するコンポーネント:

- `speed`: 文字出現速度（ms）
- `isSkipping`: クリック時に一瞬で全表示するフラグ
- `cursorCharacter`: 点滅カーソル文字（`_` や `█`）

### コンソール風エフェクト

- **Scanlines**: 画面全体に薄い横線を1pxおきに描画
- **Vignette**: 画面の四隅をわずかに暗くし、古いモニターの丸みを演出
- **RGB Shift**: テキストがタイピングされる瞬間に、ごくわずかに色収差を発生させる

### 入力待機インターフェース

選択肢の提示例:

```
[1] サーバーを再起動する
[2] ログを破棄する
[3] 接続を切断する
> _
```

キーボードの数字キー（1-3）またはテキストクリックで選択可能。

## 技術的課題と解決策

### 課題: Text オブジェクトの大量生成

Phaserの `Text` オブジェクトを大量に生成すると描画負荷が高まる可能性がある。

### 解決策の検討

1. 一つの大きな `BitmapText` を更新し続ける
2. 一定行数を超えたら古い `Text` オブジェクトを `destroy` するプール制を導入
