# テキスト管理システムの実装

**日付**: 2026-02-13  
**カテゴリ**: 設計・実装  
**影響範囲**: `src/game/managers/`, `src/game/types/`, `src/game/scenes/TerminalScene.ts`, `public/data/`

## 変更の背景

ゲーム内で表示されるテキスト、選択肢、分岐フローがハードコードされており、
シナリオの追加・変更が困難な状態でした。

非プログラマーでも編集可能な形式でシナリオを管理し、
データ駆動型のアーキテクチャに移行する必要がありました。

## 変更内容

### 主な変更点

1. **JSON形式のダイアログデータ構造を設計**
    - `DialogueNode` インターフェースの定義
    - `text` ノードと `choice` ノードの2種類をサポート
    - `nextId` による柔軟な分岐制御

2. **DialogueManager クラスの実装**
    - JSONファイルからのデータ読み込み機能
    - ノード間の遷移管理
    - 選択肢による分岐処理

3. **TerminalScene のリファクタリング**
    - ハードコードされたテキストを完全削除
    - DialogueManager を統合し、データ駆動型に変更
    - `processNode()` メソッドでノードタイプに応じた処理を実行

### 影響を受けるファイル

#### 新規作成

- `public/data/dialogue.json` - シナリオデータ

## データ構造

### DialogueNode インターフェース

```typescript
interface DialogueNode {
    id: string; // ノードID
    type: "text" | "choice"; // ノードタイプ
    text?: string; // 表示テキスト
    choices?: {
        text: string; // 選択肢テキスト
        nextId: string; // 次のノードID
    }[];
    nextId?: string | null; // 次のノードID（textタイプの場合）
}
```

### サンプルデータ

```json
{
    "nodes": [
        {
            "id": "boot_01",
            "type": "text",
            "text": "> SYSTEM BOOT_\n> CONNECTING...",
            "nextId": "choice_01"
        },
        {
            "id": "choice_01",
            "type": "choice",
            "choices": [
                { "text": "Yes, I hear you.", "nextId": "response_yes" }
            ]
        }
    ]
}
```

## 設計判断

### JSON形式を採用した理由

1. **編集の容易さ**: 非プログラマーでもテキストエディタで編集可能
2. **可読性**: 構造が明確で、シナリオの流れを把握しやすい
3. **ツール連携**: 将来的にビジュアルエディタなどのツールと連携しやすい

### TypeScript形式を採用しなかった理由

- 型安全性は魅力的だが、シナリオライターがTypeScriptを書く必要がある
- ビルドプロセスが必要になり、編集→確認のサイクルが長くなる

### ノード構造の設計

- `text` と `choice` の2種類に分離することで、責任を明確化
- `nextId` による遷移制御で、複雑な分岐も柔軟に表現可能
- ノードIDを文字列にすることで、可読性と保守性を向上

## 実装の詳細

### DialogueManager の主要メソッド

```typescript
// JSONファイルからデータ読み込み
async loadDialogueFromJSON(path: string): Promise<void>

// 指定IDのノードから開始
startDialogue(startNodeId: string): DialogueNode | null

// 選択肢を選び次のノードへ遷移
selectChoice(choiceIndex: number): DialogueNode | null

// 次のノードへ自動遷移（textノードの場合）
moveToNext(): DialogueNode | null
```

### TerminalScene の処理フロー

1. `create()` で DialogueManager を初期化
2. `startDialogue("boot_01")` で最初のノードを取得
3. `processNode()` でノードタイプに応じた処理を実行
    - `text` ノード → Typewriter で表示
    - `choice` ノード → ChoiceMenu で選択肢表示
4. ユーザー入力に応じて次のノードへ遷移

## 今後の課題・注意点

### 拡張性

- 現在は線形的な分岐のみサポート
- 今後、条件分岐（フラグ管理）やループ構造が必要になる可能性

### パフォーマンス

- 大規模なシナリオデータでも高速にアクセスできるよう、ノードマップを使用
- 現状は問題ないが、数千ノード規模になった場合の最適化が必要かもしれない

### エラーハンドリング

- 存在しないノードIDへの遷移時のエラー処理を実装済み
- JSONファイルの読み込み失敗時のフォールバック処理は今後検討

### テキスト表示位置

- 現在、応答テキストのY座標がハードコード（300px）
- スクロール機能や動的な配置システムの実装が今後必要
