## 1. ゲーム名

AI Agent Master

## 2. ゲーム概要

お題に沿ったゲームをAIに作らせる。
お題ごとに必要なリソースが変わってくるので、AIコアに適したモジュールをラインでつないで、リソースを供給することでゲーム生産を行う。

また、必要なリソースとは別のリソースをつなぐことでゲームの質を上げたり、生産速度を上げることもできる。

モジュールはまれにバグで生産停止する。これはプレイヤーが該当のモジュールに対して数回クリックするミニゲームで（もしくはコストを支払って一瞬で）解消できる。

AIは最初はとても処理が遅く、ゲームを作るのに時間がかかる。
AIを成長させるためには、AIが作ったゲームの売り上げを使う必要がある。

## 3. 仕様メモ

### 3-1. モジュールの種類

AIに接続できるモジュール・リソースは以下の通り。

-   1. ベースモジュール群
    - ロジック・モジュール
    - サウンド・モジュール
    - イラスト・モジュール

-   2. エクストラモジュール群（モジュールやAIコアに繋いだりすることで真価を発揮）
    - モジュールブースター（つないだモジュールのリソース出力速度を高める）
    - リソースメモリ（リソースを一定量ストックできる）
    - オートデバッガー（まれに起こる生産停止バグを自動で解消する）
    - コアエンハンサー（AIコアの処理速度が向上する）
    - アイデアチップ（ゲームに面白みを混ぜ、売り上げがランダムで増加する）

### 3-2. ゲームの評判について

ゲームの出来は、AIコアに投入したリソースのバランスによって決まる。
バランスが悪いときは評価が低くなる。
AIコアに接続できるライン数は限られているため、注意が必要。

### 3-4. ゲーム進行とアンロックシステム

#### 3-4-1. 基本コンセプト

プレイヤーは最初、簡単なゲーム（必要なリソースが少ないゲーム）のみを作成できる。
ゲームを作成して売り上げを得ることで、より複雑なゲームタイプがアンロックされていく。

#### 3-4-2. ゲームタイプの難易度設計

ゲームタイプは以下のような段階的な難易度構造を持つ：

**初級ゲーム（最初から利用可能）**

- 必要リソース: 少ない（例: ロジックのみ、またはロジック+サウンド）
- 例: シンプルなパズルゲーム、テキストベースゲーム
- 売上期待値: 低〜中

**中級ゲーム（アンロック条件: 総売上 X 円 or 累計販売本数 Y 本）**

- 必要リソース: 中程度（例: ロジック+サウンド+イラスト）
- 例: アクションゲーム、RPG
- 売上期待値: 中〜高

**上級ゲーム（アンロック条件: 総売上 XX 円 or 累計販売本数 YY 本）**

- 必要リソース: 多い（バランスの取れた大量のリソースが必要）
- 例: オープンワールドゲーム、大作RPG
- 売上期待値: 高

#### 3-4-3. ゲームタイプの切り替え

- プレイヤーは、アンロック済みのゲームタイプをいつでも切り替え可能
- UIから選択することで、AIコアが作成するゲームのタイプが変更される
- ゲームタイプによって必要なリソースの種類・量・バランスが変化する

#### 3-4-4. 売上計算とアンロック条件

```
累計データの管理:
- 総売上金額（全ゲームタイプの合計）
- 累計販売本数（全ゲームタイプの合計）
- ゲームタイプ別の実績も記録

アンロック判定:
- 総売上 OR 累計販売本数のいずれかの条件を満たせばアンロック
- 条件は段階的に厳しくなる
```

#### 3-4-5. 実装上の考慮事項

- アンロック状態は永続化（LocalStorage等）
- 売上データもセーブ/ロード可能
- UI上でアンロック済み/未アンロックのゲームタイプを視覚的に区別
- 次のアンロックまでの進捗を表示（例: 「あと 10,000 円で新しいゲームタイプがアンロック！」）
