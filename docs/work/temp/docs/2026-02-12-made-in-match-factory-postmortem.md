# 開発後記：『Made in Match Factory』

パズルを通じてゲームを生産するシミュレーションゲーム **『Made in Match Factory』** を開発しました。
（旧題：AI Agent Master）

- **制作期間:** 約2週間（2026/01/30 - 2026/02/12）
- **使用技術:** Phaser 3 (TypeScript + Vite + Electron)

## コンセプト

本作は **「パズルでゲームを生産する」** ことをテーマにしたシミュレーションパズルゲームです。
当初はモジュールをラインで接続する複雑なシミュレーションを想定していましたが、**「直感的な楽しさ」** を優先し、親しみやすいマッチ3パズルをコアメカニクスに据えました。

「工場（Factory）」で「製造（Made in）」するという無機質な世界観と、リズミカルなパズル操作の融合を目指しました。

## Good：うまくいった点・アピールポイント

- **アーキテクチャの確立:** Sceneクラスを軽量に保ち、`State Pattern` や `Observer Pattern` を導入することで、保守性の高いコードベースを構築できました。特にパズルロジックと描画（Scene）の分離は、機能追加を容易にしました。
- **イベント駆動の実装:** パズルエリアでのアクション（タイル消去）と、ゲーム生産エリア（リソース増加・ゲーム完成）をイベントで疎結合に連携させることで、複雑な依存関係を回避しつつ、爽快な連動感を実現しました。
- **直感的な操作への転換:** 開発初期の「ライン接続システム」から「マッチ3パズル」へのピボットは英断でした。これにより、プレイヤーは複雑な学習なしに「リソース管理」の本質を楽しめるようになりました。

## Bad / Next：反省と次への課題

- **機能の取捨選択:** 開発期間の都合上、「ゲームタイプのアンロック」や「モジュールカスタマイズ」といった深みを持たせる要素を簡略化しました。これらは長期的なリプレイ性のために重要な要素であるため、今後のアップデート課題です。
- **演出面の強化:** パズル連鎖時の爽快感や、ゲーム完成時の達成感を高めるための演出（パーティクル、SE、アニメーション）にはまだ改善の余地があります。
- **モバイル対応:** 現状はPC（デスクトップ/ブラウザ）向けですが、UI配置を調整してスマートフォンでも遊べるようにすることで、より手軽に楽しんでもらえる可能性があります。

## まとめ

本作は、技術的な挑戦（Phaser 3 × TypeScript × Electron）と、ゲームデザインの大きな転換（シミュレーション → パズル）を経て完成しました。
「設計の良さが開発を助ける」ことを実感したプロジェクトでもあり、今後の開発における重要な資産となりました。
